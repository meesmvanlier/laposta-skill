# Laposta API: every endpoint

Generated by `scripts/generate-reference.py` from the API source. Do not edit by hand.

Base URL `https://api.laposta.nl/v2`. Authentication is HTTP basic with the API key as the
username and an empty password, so in curl that is `-u YOUR_KEY:` including the
colon. Every operation can return `400`, `401` and `429`; see
`errors-and-limits.md` for what those mean and for the numeric error codes,
which are not part of the machine readable spec.

## Lists

A list holds the subscribers you send newsletters to. Use these endpoints to create lists, retrieve them and empty them.

### POST /list/{list_id}/members

Synchronizing a list (bulk) (`lijstSynchroniserenBulk`, returns `200`, **needs confirmation**)

Adds, updates or unsubscribes multiple subscribers in one request. This endpoint is off by default: an account without access gets a 401 with the message "Not permitted to issue bulk requests (1)". Contact Laposta to have it enabled for your account.

Required:

| Parameter | In | Type | Meaning |
| --- | --- | --- | --- |
| `list_id` | path | string | The id of the list. You find it in the response of Get all lists, and in the application in the URL of the list. |
| `actions` (JSON body) | form | string | An array with at least one of the following options: add, update, or unsubscribe_excluded. These determine whether members may be added, updated and/or unsubscribed (read details below). |
| `members` (JSON body) | form | object | An array with member objects. A minimum of 1, maximum of 500,000. |
| `member_id` (inside `members[]`) | form | string | The id of the subscriber, or simply their email address. Both work. |
| `email` (inside `members[]`) | form | string | The email address of the relation to be changed or added. If the member_id is also specified, then a new email address can be specified here for the existing relation. |
| `custom_fields` (inside `members[]`) | form | object | A JSON object where the key is the name of the extra field and the value is the value of the extra field. |

Optional:

| Parameter | In | Type | Meaning |
| --- | --- | --- | --- |
| `mode (verouderd)` (JSON body) | form | string | For backwards compatibility you can still pass edit, add or add_and_edit, but this parameter is being phased out. Do not send mode together with actions. |
| `source_url` (inside `members[]`) | form | string | The URL from which the relation was registered. |

Response: `SyncResult` (see `schemas.md`).

### POST /field/{field_id}

Modifying fields (`veldWijzigen`, returns `200`)

You will only have to include the parts that need to be modified. Parts that are not mentioned will keep their current values. As soon as a part is mentioned it does get checked, and thus can cause an error message. This error message contains a code with a message. See above under 'Error messages' what these codes stand for. Pass options_full as a complete replacement for the option list. The key of each entry determines the operation: You may also pass options_full as an array of {"id", "value"} objects — the same shape as the response. The API will handle both formats.

Required:

| Parameter | In | Type | Meaning |
| --- | --- | --- | --- |
| `list_id` | form | string | The id of the list. You find it in the response of Get all lists, and in the application in the URL of the list. |
| `required` | form | boolean | Is this a mandatory field? |

Optional:

| Parameter | In | Type | Meaning |
| --- | --- | --- | --- |
| `name` | form | string | A name for this field |
| `datatype` | form | string (text, numeric, date, select_single, select_multiple) | The data type of this field (text, numeric, date, select_single, select_multiple) |
| `datatype_display` | form | string (select, radio) | Only applicable for select_single: the desired display (select, radio) |
| `options_full` | form | array | The full set of options for a select_single or select_multiple field, as a key/value map of id → label. The key controls what happens to each option: Existing numeric ID (e.g. "2") — keeps or modifies the option. Changing the label updates it in-place; the ID stays the same, so existing member data is preserved. Non-numeric key (e.g. "new-0") — adds a new option; a fresh ID is assigned automatically. Omitting an existing ID — deletes that option. Always include every option you want to keep. Must be sent as JSON. Alternative format: instead of a key/value map you may also pass an array of objects in the same shape as the response: [{"id": "1", "value": "Red"}, {"id": "new-0", "value": "Orange"}]. The API will normalise this automatically. |
| `defaultvalue` | form | string | The default value (will be used in the absence of this field) |
| `in_form` | form | boolean | Does this field occur in the subscription form? (boolean) |
| `in_list` | form | boolean | Is this field visible in Laposta's overview? (boolean) |

Response: `FieldEnvelope` (see `schemas.md`).

Filling in the content of a campaign The campaign can either be filled directly with html, or through a URL, in which case Laposta imports the html found at the specified URL. If it does succeed in importing the html, but problems were found during the import, they are shown in the variable report in the response. These may include: Solving these problems is not necessary in order to properly send the newsletter, but it is highly recommended. In the case of a free account, our advertising is added to the bottom of the newsletter. If the offered html does not contain an unsubscribe link, it will simply be added by our program.
